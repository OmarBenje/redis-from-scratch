## Make

- Recette = **tabulation**, jamais des espaces. `missing separator` veut toujours dire ça. Vérif : `cat -A` → `^I`.
- `:=` (immédiat) par défaut, pas `=` (différé).
- Une cible, c'est ce qui **sort**. Les `.c` sont les feuilles, l'exécutable la racine.
- `$@` cible · `$<` 1re dépendance · `$^` toutes.
- `.PHONY` : sans elle, un fichier nommé `clean` fait dire `is up to date` et `make clean` ne fait plus rien.
- Dépendances avant recette : `fclean: clean` → recette de `clean`, puis celle de `fclean`.
- Une variable n'agit que là où on écrit `$(VAR)`. Définir `LDFLAGS` en haut ne suffit pas.
- **⚠️ Règle de motif dont une dépendance manque = jetée en silence.** Repli sur la règle intégrée `%.o: %.c`, qui ignore les headers. Signature : `gcc -c -o main.o main.c` (intégrée) vs `gcc -c main.c -o main.o` (la mienne). `make -r` révèle le problème.
- → `SRCS`/`HEADERS` = inventaire du disque **maintenant**. Un `.c` en trop = erreur franche ; un `.h` en trop = panne muette.
- **⚠️ Modifier un `.h` non déclaré** → pas de recompilation → `.o` en désaccord sur la taille d'un `struct` → segfault sans avertissement. Réflexe : `make re`.
- `make -n` (montre sans exécuter) · `make -B` (force tout) · `$(info $(VAR))`.
- Chaque ligne de recette = un shell neuf → `cd src && gcc ...`, jamais sur deux lignes.

## Compilation

- 4 étapes : préproc → compil → assemblage → **linking**. La coupure avant le linking est ce qui rend make utile.
- Un `.o` est incomplet (trous vers les fonctions externes). `file` dit `relocatable` vs `executable`.
- `-o` = **où** · `-c` = **jusqu'où** (arrêt au `.o`) · `-g` = **quoi** (debug). D'où : le « quoi » dans `CFLAGS`, le reste dans les recettes.
- `-g` : sans → `0x401136 in ?? ()` ; avec → `store_get (s=0x0, ...) at store.c:42`. Aucun coût à l'exécution.
- **⚠️ `gcc -o fichier.c fichier.c` écrase la source.** Code perdu.
- Le nom de sortie est indépendant du nom de la source : `gcc -o toto server.c` marche.

### Header ≠ bibliothèque

| | Apporte | Étape |
|---|---|---|
| `#include` | prototype + constantes | compilation |
| `-lm`, `-lpthread` | le code | linking |

| Erreur | Étape | Manque |
|---|---|---|
| `implicit declaration of function` | compilation | le header |
| `undefined reference to` | linking | la bibliothèque |

- La libc est liée d'office → aucun `-l` pour `socket`, `printf`, `close`. Vérif : `ldd server`.
- Un `#define` (`AF_INET`) ne peut venir **que** d'un header — ce n'est pas du code.
- **ASan doit être passé aux deux étapes** (`CFLAGS` *et* `LDFLAGS`). Sinon : `undefined reference to '__asan_init'`.
- *(Culture : `-lsocket -lnsl` = Solaris. Pas Linux, ne pas recopier.)*

## Langage C

- **⚠️ La portée d'un identificateur commence à la fin de son déclarateur**, pas de l'instruction : `int socket = socket(...)` appelle la variable, pas la fonction. Même piège que `int x = x + 1;`.
- → nommer `listen_fd` / `client_fd` dès le départ. Deux fd, deux `close()`.
- Littéral composé (C99) : `&(int){1}` = objet anonyme + son adresse, vivant jusqu'à la fin du bloc. (`&1` serait illégal.)
- `sizeof(yes)` > `sizeof(int)` : suit le type de la variable ; écrire le type à la main devient un bug muet s'il change.
- `if (x == 1);` → le bloc suivant s'exécute **toujours**.

## `perror` / `errno`

- Affiche sur **stderr** : `socket: Permission denied`. Lui passer le nom de l'appel qui a échoué.
- **Détecter l'échec par la valeur de retour, jamais par `errno`** — il n'est pas remis à zéro en cas de succès.
- **Appeler `perror` immédiatement** : presque tout appel de fonction écrase `errno`, y compris un `printf` intercalé.
- **Il n'arrête pas le programme.** Sans `return 1;` derrière → cascade d'erreurs dont seule la première compte.
- stderr ≠ stdout : `./server 2> erreurs.txt` isole les erreurs.
- `strerror(errno)` (`<string.h>`) pour composer un message riche.
- Tester d'abord, sortir si erreur, afficher ensuite.

## Codes de retour / `$?`

- `$?` = le `return` de `main`. `0` succès, non nul échec.
- `1` échec · `126` pas exécutable · `127` introuvable · `134` `abort()` (ASan) · `139` **segfault** (128+11).
- `make && ./server` : ne lance pas l'ancien binaire si la compil rate.
- `Error 1` dans make = le code rendu par gcc. Idem, `rm -f` dans `clean` évite que `rm` fasse échouer la cible.
- **⚠️ `$?` est écrasé par chaque commande, y compris `echo`.** Le lire tout de suite ou `code=$?`.

## Descripteurs

- **⚠️ Le noyau rend le plus petit fd LIBRE, pas systématiquement `3`.** Un fd hérité du parent (IDE gardant un tube) → on obtient `4`. Constaté en vrai.

  ```
  ./server                      → 3
  ./server 3< /etc/hostname     → 4
  ./server 0<&-                 → 0
  ```
  Inspecter : `ls -l /proc/self/fd`.
- → jamais de numéro de fd en dur.
- → **un fd valide peut valoir `0`** : d'où l'échec à `-1`. `if (fd)` rejetterait un fd correct — et là, la socket *est* stdin.

## Sockets

- `socket(domain, type, protocol)` : `AF_INET` (IPv4) · `SOCK_STREAM` (TCP, flux ordonné fiable) · `0`.
- `0` = « protocole par défaut pour cette combinaison », pas « TCP » : le même `0` donne UDP avec `SOCK_DGRAM`.
- `AF_INET` va avec `struct sockaddr_in` (`_in` = internet).
- `setsockopt` a 5 arguments parce qu'elle est **générique** : chaque option a son type (`int`, `struct linger`…), d'où `void *` + taille.
- Le `level` se déduit du préfixe : `SO_*` → `SOL_SOCKET`, `TCP_*` → `IPPROTO_TCP`.
- `SO_REUSEADDR` contourne `TIME_WAIT` (~60 s de rétention du port). Sans elle : `bind: Address already in use` à chaque relance. **À poser avant `bind()`.**
- **⚠️ `SO_REUSEADDR` ne couvre PAS un processus qui écoute vraiment.** Elle ignore les *résidus* (`TIME_WAIT`), pas un `LISTEN` vivant — sinon n'importe qui pourrait détourner le port d'un autre.
- Devant `Address already in use`, trancher avec `ss -tlnp | grep 6379` : aucune sortie → `TIME_WAIT` (attendre) ; une ligne → un processus détient le port, elle donne son PID → `kill <pid>`. Cas le plus fréquent : un `./server` oublié dans un autre terminal.
- **⚠️ Conventions de retour différentes** : `socket()` rend un fd (`-1` = échec), `setsockopt()` rend `0` en cas de succès. Toujours lire **RETURN VALUE**.
- `bind()` attache une **adresse locale = IP + port**, pas juste un port. Une socket sort de `socket()` anonyme : rien ne permet de la désigner de l'extérieur.
- `bind` ne **connecte** rien : aucun paquet, aucune machine distante. Déclaration purement locale auprès du noyau. La connexion, c'est `accept()` / `connect()`.
- `INADDR_LOOPBACK` (`127.0.0.1`, machine locale) vs `INADDR_ANY` (`0.0.0.0` = joker « toutes mes interfaces », donc le réseau). Redis écoute en loopback par défaut — un Redis sur `0.0.0.0` sans mot de passe se fait piller.
- **⚠️ `htons()` obligatoire sur le port** (ordre réseau = gros-boutiste, x86 = petit-boutiste). L'oublier ne produit **aucune erreur** : `bind` réussit et on écoute sur `61464` au lieu de `6379`.
- Un **client** n'appelle pas `bind()` : le noyau lui donne un port éphémère au `connect()`. `bind` explicite = pour qui veut une adresse **prévisible**, donc le serveur.
- `struct sockaddr_in` (`<netinet/in.h>`) : `sin_family` = `AF_INET` · `sin_port` = `htons(port)` · `sin_addr.s_addr` = `htonl(ip)`. `sin_addr` est une structure à un champ, d'où le double point.
- `htons` = *host to network **short*** (16 bits, port) · `htonl` = ***long*** (32 bits, IPv4). Le suffixe donne la taille.
- **⚠️ `INADDR_LOOPBACK` a besoin de `htonl()`.** Invisible avec `INADDR_ANY` qui vaut `0` (inversé ou pas, `0` reste `0`) — d'où les tutos qui l'omettent.
- **⚠️ `memset(&addr, 0, sizeof(addr))` avant de remplir.** Variable locale = ordures de la pile, et `sin_zero` (8 octets de padding) est lu par le noyau sans qu'on le remplisse. Ni ASan ni `-Wall` n'attrapent ça : la structure *est* partiellement initialisée.
- **Cast obligatoire** : `bind(fd, (struct sockaddr *)&addr, sizeof(addr))`. Même raison que le `void *` de `setsockopt` — l'API doit accepter `sockaddr_in` (IPv4), `sockaddr_in6`, `sockaddr_un`, de tailles différentes. Pas de polymorphisme en C → type générique + taille explicite. Le seul champ commun est la famille, en premier : c'est par lui que le noyau interprète le reste.

## Outils

- `man 2 socket` — section 2 = appels système. Lire **SYNOPSIS** (les includes !) et **RETURN VALUE**.
- `strace ./server` — les appels réellement vus par le noyau :
  ```
  socket(AF_INET, SOCK_STREAM, IPPROTO_IP) = 3
  setsockopt(3, SOL_SOCKET, SO_REUSEADDR, [1], 4) = 0
  ```
  On y lit le fd, le succès, et `[1], 4` = la valeur pointée par `&(int){1}`.
- **⚠️ ASan noie `strace`** sous ses propres appels. Filtrer sur le contenu : `strace ./server 2>&1 | grep -E 'AF_INET|SO_REUSEADDR'`.
- **Forcer un échec pour tester ses `perror`** : `( ulimit -n 3 ; ./server )` → `socket: Too many open files`.
- `ldd server` · `ss -tlnp | grep 6379`.

## Git

- Versionner ce qu'on écrit, ignorer ce que `make` fabrique (`*.o`, `*.d`, exécutable, `.idea/`, `vgcore.*`).
- **Slash initial = ancré à la racine** : `/server` n'ignore que l'exécutable, `server` ignorerait aussi `src/server/`.
- **⚠️ `.gitignore` n'agit que sur les fichiers non suivis.** Déjà commité → `git rm --cached <fichier>`.
